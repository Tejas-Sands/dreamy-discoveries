# Story production improvements

User intent: prepare at least 50 distinct, enjoyable preschool moral stories in an external chat, import them singly or in batches, and produce daily episodes without requiring a fresh LLM script. Also improve current writer fallback and add parent-directed subscription reminders.

1. LLM reliability: validate received completions inside the bounded provider chain. Reject short, invalid, empty or truncated scripts and advance to another free provider. Preserve the one writing stage, local checks, deadline, standby fallback and slug reruns. Cover real failure modes with mocked transport and planner integration tests.
2. Subscription reminders: show a deterministic visual at a suitable scene boundary near the midpoint and during the end card. Keep duration and voice unchanged. Default to parent-directed subscribe text because Made for kids notifications are unavailable; support bell artwork/text only when explicitly enabled. Verify placement math, rendering and a preview still.
3. Story tools: `npm run stories:brief` exports a small ignored folder containing a self-contained chat prompt, compact inventory/history, JSON schema and valid example. Default writing batch is three; overall goal is 50. Include the six closed cast cards, current vocabulary and backgrounds, used and unused story summaries, and intentional location changes.
4. `npm run stories:feed -- FILE_OR_DIRECTORY` validates every story before writing. Accept a single object, JSON array, or `{stories:[...]}`. Reject unsafe/colliding slugs, invalid cast/background/speaker fields, short scripts and malformed batches. Run the Director on new scripts; append them to the standby manifest and daily slug queue. Repeating identical input is a no-op; committed scripts are never overwritten. Support `--dry-run` and `--no-queue`.
5. Test imports/exports in temporary workspaces: no network, preserve production library, all-or-nothing validation, no duplicate queue rows, existing slug reruns, multiple scene backgrounds. Document the two-command workflow and remaining need for human story review. Run full tests and TypeScript checks before integration.
